## Notes for Higher-Level Synthesis

- Boundary code, not domain logic. This directory only declares presentation: XML views, actions, menus and QWeb templates. It is the UI shell for the `sale.order` aggregate. Belongs with the Sales order-management component, together with the sale models and portal controllers.
- Heavy extension layer. Most `ir.ui.view` records here are `inherit_id` extensions of views owned by account, product, sales_team, payment, base and utm. Higher-level synthesis should record these as dependencies on those modules, not as sale-owned screens.
- `sale_order_views.xml` (1133 lines) holds most of the sale-owned screens. It has the primary `view_order_form`, the list/kanban chain (`sale_order_tree` → `view_order_tree` / `view_quotation_tree` → `*_with_onboarding`), and the action bindings for Orders, Quotations, To Invoice and Upselling.
- Portal templates (`sale_portal_templates.xml`) are the customer-facing layer. Acceptance and decline POST to controller routes outside this directory, so the component that owns the portal should be linked to the controllers doc.
